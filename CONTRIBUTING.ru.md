# Как помочь Cubr

[English version](CONTRIBUTING.md)

Спасибо, что хочешь помочь. У проекта один мейнтейнер, поэтому быстрее всего
вливается короткий сфокусированный pull request по правилам ниже.

## Перед началом

- **Баги:** заведи issue — шаги воспроизведения, что ожидалось и что
  случилось. Если дело в камере, укажи кубик (с наклейками или stickerless) и
  освещение: зрение чувствительно к обоим.
- **Фичи:** сначала issue с описанием идеи. Скоуп держится узким намеренно,
  поэтому необсуждённая фича может быть отклонена даже с хорошим кодом.
- **Уязвимости:** не заводи публичный issue. Сообщи приватно через «Report a
  vulnerability» на вкладке Security в GitHub или напрямую мейнтейнеру.

## Локальный запуск

Бэкенд (нужны Docker для Postgres, Python 3.12, [`uv`](https://docs.astral.sh/uv/)):

```bash
cd backend
cp .env.example .env
docker-compose up -d
uv sync
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

Фронтенд (Node 22.12+ или 24):

```bash
cd frontend
npm ci
npm run dev
```

Подробности — [`backend/README.md`](backend/README.md).

## Проверки

CI гоняет всё это на каждый pull request; прогони локально перед пушем.

```bash
# бэкенд
cd backend
uv run ruff check . && uv run ruff format --check . && uv run mypy app && uv run pytest -q

# фронтенд
cd frontend
npx prettier --check "src/**/*.{ts,tsx,css}" "tests/**/*.{ts,tsx}" "scripts/*.mjs"
npm run typecheck && npm run lint && npm test && npm run build
```

`npm run build` заодно проверяет бюджет размера входного чанка — сборка сверх
бюджета падает.

## Правила изменений

- **Тесты обязательны.** Новое поведение — с тестами; фикс бага — с тестом,
  который без фикса падает.
- **Одно изменение на pull request.** Не смешивай фичу с посторонним
  рефакторингом или переформатированием.
- **Коммиты** — по [Conventional Commits](https://www.conventionalcommits.org/ru/):
  `feat(scope): ...`, `fix(scope): ...`, `docs: ...`, `chore: ...`. Сабж
  короткий и говорит, что изменилось для пользователя, а не какой файл тронут.
- **Строки для пользователя** — через `t()`, и каждая новая строка сразу
  получает ключ в `frontend/src/i18n/en.ts`. Ключ — сама русская строка.
  Числительные переводятся фразой целиком через `i18n/plural.ts`.
- **Изменения схемы БД** — с миграцией Alembic.
- **Никаких секретов в репозитории.** Настройки живут в `.env` (в git-ignore);
  новые переменные добавляй в `.env.example` с заглушкой.
- **Файлы небольшие.** Предел — около 400 строк; дели файл раньше, чем он
  его перерастёт.

## Pull request

1. Форкни репозиторий и сделай ветку от `main` (`fix/...`, `feat/...`).
2. Внеси изменение, прогони проверки выше.
3. Открой pull request в `main`. Опиши, что изменилось и зачем и как ты это
   проверял(а). Для UI помогают скриншоты.
