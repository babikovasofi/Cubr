## Часть A. Исправление порядка ритуала (баг документации)

**Проблема:** в старых доках/прототипе скрамбл показывался ДО того, как система увидела
собранный кубик. Нелогично: калибровка цветов и подтверждение честного стартового состояния
требуют показать камере именно **собранный** кубик — до любого перемешивания.

**Правильный порядок (заменяет userflow §5.1 шаги 1–3):**
```
1. [СНАЧАЛА] Игрок показывает камере СОБРАННЫЙ кубик
   → калибровка/подстройка цветов (Часть B), подтверждение честного старта
2. Сервер выдаёт скрамбл (в дуэли — одинаковый обоим)
3. Игрок мешает по визуальной инструкции / нотации (см. [[feature-scramble-visual]])
4. Показывает перемешанный кубик → сверка с эталоном скрамбла
5. Две руки + кубик на стол → готовность
6. Синхронный старт → сборка → руки на стол → стоп
7. Показ собранного кубика → подтверждение → результат
```

**Фазы FSM сценария (Этап 0):**
`CALIBRATE_SOLVED → SCRAMBLE_SHOWN → SCRAMBLE_VERIFY → READY → SOLVING → STOPPED → SOLVE_VERIFY`.
Экран калибровки — **первый** экран цикла, не «где-то в настройках».

## Часть B. Профили кубиков (новая фича)

**Идея:** игрок регистрирует свои кубики один раз (показ 6 граней собранного + название,
напр. «GAN 356»). Сайт запоминает цветовой профиль. Перед игрой игрок выбирает, каким кубиком
собирает — система уже знает цвета. Кубиков может быть несколько.

**Ключевая проблема (нельзя игнорировать):** профиль снят при конкретном освещении. Другой свет
→ сохранённые эталоны врут → красный/оранжевый снова путаются → подрыв главной митигации R1.
Полностью доверять сохранённому профилю нельзя.

### Трёхуровневая схема
| Уровень | Когда | Действие игрока | Время |
|---|---|---|---|
| **Регистрация кубика** | Один раз на кубик | Показывает 6 граней + называет | ~20 сек |
| **Быстрая подстройка** | Каждую сессию (шаг 1 ритуала) | Показывает ОДНУ грань собранного | ~3 сек |
| **Полная перекалибровка** | Если подстройка не сошлась | Показывает 6 граней заново | ~20 сек |

**Как работает быстрая подстройка:** по одной грани система видит 9 наклеек известного цвета →
вычисляет сдвиг между сохранённым эталоном и текущим наблюдением (коррекция баланса белого/яркости)
→ применяет сдвиг ко всем 6 эталонам профиля. **Критерий успеха:** после сдвига попарные ΔE между
6 эталонами остаются выше порога различимости; иначе → полная перекалибровка.

**Что даёт:** шаг 1 ритуала 15–20 сек → ~3 сек, честность сохранена (система всё равно видит
собранный кубик в начале каждой игры — подтверждение старта из Части A остаётся; одна грань +
упрощённый прогон остальных пяти, либо полный показ — решить на прототипе).

### UX
- **Регистрация** (Настройки → «Мои кубики» → «Добавить»): мастер 6 граней → название (обяз.) +
  заметка (опц.) → превью считанных цветов → подтвердить. Первый кубик авто-«основной».
- **«Мои кубики»:** список (название, палитра-миниатюра 6 цветов, дата, метка «основной»);
  действия — переименовать / сделать основным / перекалибровать / удалить; **лимит MVP 5** кубиков.
- **Выбор перед игрой:** селектор «Кубик: [основной ▾]» в лобби; по умолчанию основной.
  Нет кубиков (новичок) → регистрация первого встроена в онбординг (заменяет старый шаг «проверка
  камеры» → «проверка камеры + регистрация кубика»).
- **В ритуале (шаг 1):** «Покажи собранный кубик [название]» → одна грань → ✅ или просьба полной
  перекалибровки. Показал не тот кубик (не бьётся ни с одним профилем) → «Похоже, другой кубик.
  Выбрать другой профиль / зарегистрировать новый?».

### Модель данных (добавить в tech-details)
```
cubes:  id, user_id, name, note?, is_primary,
        color_profile JSONB,   -- 6 эталонов в Lab: {W:[L,a,b], Y:.., R:.., O:.., B:.., G:..}
        created_at, recalibrated_at
solves: + cube_id (FK cubes.id, nullable для старых записей)
```
Профиль храним в **Lab** (в нём же ΔE и подстройка), не RGB.

### Бэклог (roadmap, не MVP)
Статистика по кубикам («на GAN 356 average лучше на 1.2 сек»); кубик в публичном профиле;
V3 «каким кубиком собран рекорд» в лидербордах.

## План работ
**Этап 0 (прототип):**
- Исправить порядок фаз FSM (Часть A).
- Снятие профиля с 6 граней → localStorage (без сервера).
- Быстрая подстройка по одной грани + критерий «сошлось / не сошлось».
- Тест: профиль снят днём → подстройка при лампе → точность чтения не деградирует.

**Этап 2 (аккаунты):**
- Таблица `cubes`, CRUD-эндпоинты, лимит 5.
- Мастер регистрации + экран «Мои кубики» в настройках; регистрация первого в онбординге.
- Селектор кубика перед игрой; `solve.cube_id` пишется в результат.

## Критерии приёмки
1. Новичок регистрирует кубик в онбординге ≤ 30 сек и сразу играет.
2. Возвращающийся проходит шаг 1 ритуала за ~3 сек (одна грань).
3. Смена освещения между сессиями не ломает чтение (тест выше).
4. Игрок с двумя кубиками переключается без перекалибровки.
5. Показ незарегистрированного кубика детектится → понятное действие.
