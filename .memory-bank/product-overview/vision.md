# Cubr — соревновательная платформа для спидкубинга

> Мастер-документ (ТЗ) — итог сессии заказчик/ПМ, стартовая точка разработки.
> «CubeDuel» — старое рабочее название; канонично **Cubr**.

---

## 1. Видение

Веб-платформа, где спидкуберы соревнуются друг с другом онлайн. Ключевая фишка — **компьютерное зрение вместо судьи**: камера проверяет честность перемешивания, фиксирует старт/стоп по рукам на столе и подтверждает, что кубик собран. Долгосрочно — социальная сеть для кубинг-сообщества.

**Цель:** готовый продукт для реальных пользователей (не учебное демо).

---

## 2. MVP — что входит

### 2.1 Режимы
| Режим | Описание |
|---|---|
| **Дуэль · Фаст** | 1 сборка, оба игрока онлайн одновременно, один скрамбл на двоих |
| **Дуэль · Классика (Ao5)** | 5 сборок; лучшее и худшее время отбрасываются, среднее из трёх оставшихся (как WCA average) |
| **Еженедельный турнир** | Одна сборка на общем скрамбле недели, все результаты в общую таблицу, обновляется каждую неделю |

### 2.2 Кубки и матчмейкинг
- За победы/участие игроки получают **кубки** — единая валюта рейтинга
- Рандомный подбор соперника с похожим количеством кубков
- Режим «риск»: можно вызвать игрока с большим количеством кубков (награда выше)
- Количество кубков за победу/поражение — балансируется позже, в MVP простая формула

### 2.3 Ритуал сборки (сценарий игрока)
1. Сервер выдаёт **скрамбл** (последовательность типа `R U' F2 D ...`) — в дуэли одинаковый для обоих
2. Игрок перемешивает кубик по скрамблу
3. Показывает кубик камере (все 6 граней) → система сверяет состояние с эталоном скрамбла → ✅ честно перемешан
4. Кладёт **две руки на стол**, кубик на столе → система видит готовность
5. Синхронный **сигнал старта** (в дуэли — когда оба готовы) → таймер пошёл
6. Игрок собирает кубик
7. Кладёт **две руки на стол** → таймер стоп
8. Показывает кубик камере → система подтверждает: собран
9. Результат фиксируется, в дуэли — сравнение и победитель

### 2.4 Статус соперника в дуэли
Игрок видит только **статус** соперника (не видео): `перемешивает → проверка → готов → собирает → закончил → результат`.

### 2.5 Аккаунты и профиль
- Регистрация обязательна
- **Email + пароль** (подтверждение почты, восстановление пароля) **+ вход через Google (OAuth)**
- Профиль: ник, аватарка, кубки, лучшее время (Фаст и Ao5), история сборок
- Таблица лидеров недельного турнира

### 2.6 Честность (антично-чит, критично для продукта)
- Скрамбл генерирует **сервер**, клиент его не выбирает
- Зрение работает в браузере (быстро, приватно), но **ключевые кадры** (кубик после скрамбла, кубик в конце) уходят на сервер для повторной проверки
- Сервер сверяет **тайминги** событий (нельзя прислать «собрал за 0.5 сек» без последовательности событий)
- Результат засчитывается только после серверной валидации

## 3. Не входит в MVP (бэклог V2+)
- Турниры по сетке / плей-офф
- Друзья, подписки, личные сообщения, лента (соцсеть)
- Просмотр видео сборки соперника / реплеи
- Другие головоломки (2x2, 4x4, пирамидка)
- Мобильное приложение
- График прогресса в профиле (можно добавить рано, если захочется)

## 4. Технический стек

| Слой | Выбор | Почему |
|---|---|---|
| Фронтенд | **React + TypeScript (Vite) + Tailwind** | Лучшая экосистема для камеры/CV в браузере; TS — задел на рост проекта |
| Зрение: руки | **MediaPipe Hands (JS)** — в браузере | Готовый детект рук, работает на любом ноуте, уже знакомая технология |
| Зрение: кубик | **Своя логика**: canvas + классификация цветов наклеек по HSV | Исследовательская часть; готовых надёжных JS-решений нет — это твоя ML-зона |
| Кубик-логика | **cubejs / min2phase (JS)** | Применить скрамбл к виртуальному кубику, получить эталон для сверки |
| Бэкенд | **Python + FastAPI** | Твой сильный язык; WebSockets и async из коробки; серверная CV-доп.проверка на OpenCV в том же языке |
| Реалтайм | **WebSockets (FastAPI)** | Комнаты дуэлей, статусы, синхронный старт |
| БД | **PostgreSQL + SQLAlchemy** (локально можно начать с SQLite) | Реляционные данные: игроки, дуэли, результаты, турниры |
| Авторизация | **fastapi-users**: email+пароль (argon2) + Google OAuth, JWT в httpOnly cookies | Не писать безопасность с нуля |
| Хостинг | Фронт — **Vercel**; бэк + Postgres — **Railway / Render** | Бесплатный старт, простой деплой |

### Архитектура
```
Браузер (React + TS + MediaPipe JS + логика кубика)
   │  REST      — логин, профиль, результаты, лидерборд
   │  WebSocket — дуэль: матчмейкинг, статусы, старт, финиш
   │  Кадры     — ключевые снимки для серверной валидации
   ▼
FastAPI (Python)
   ├─ генерация скрамблов, проверка состояния кубика
   ├─ валидация таймингов, начисление кубков
   ├─ матчмейкинг, комнаты дуэлей
   └─ недельные турниры (cron: смена скрамбла раз в неделю)
   │
   ▼
PostgreSQL
```

## 5. Модель данных (набросок)

```
users:        id, email, password_hash, google_id?, nickname, avatar_url,
              cups, best_single_ms, best_ao5_ms, created_at
duels:        id, mode (fast|ao5), scramble(s), player1_id, player2_id,
              status, winner_id, created_at
solves:       id, user_id, duel_id?, tournament_id?, scramble, time_ms,
              status (valid|dnf|rejected), verify_frames_ok, created_at
tournaments:  id, week_start, scramble, status
trophy_log:   id, user_id, delta, reason, created_at
```

## 6. План разработки (этапы)

Порядок выстроен так, чтобы **самый рискованный кусок (зрение кубика) прототипировался первым** — если он «взлетит», остальное точно получится.

### Этап 0 — Прототип зрения (риск-киллер)
- [ ] Страница с камерой: MediaPipe Hands детектит две руки на столе
- [ ] Детект кубика в кадре и чтение 9 наклеек одной грани (HSV-классификация цветов)
- [ ] Чтение всех 6 граней (игрок поворачивает кубик по подсказкам на экране)
- [ ] Сверка считанного состояния с эталоном через cubejs
- [ ] Критерий успеха: стабильно читает кубик при обычном комнатном освещении

### Этап 1 — Соло-таймер (ядро без сети)
- [ ] Полный ритуал сборки локально: скрамбл → проверка → руки → старт → стоп → проверка сборки
- [ ] Точный таймер, отображение времени
- [ ] Это уже можно показывать людям и собирать фидбек по зрению!

### Этап 2 — Бэкенд и аккаунты
- [ ] FastAPI-проект, PostgreSQL, модели данных
- [ ] Регистрация email+пароль, подтверждение почты, Google OAuth
- [ ] Профиль, сохранение результатов сборок, история

### Этап 3 — Серверная честность
- [ ] Генерация скрамблов на сервере
- [ ] Отправка ключевых кадров, серверная повторная проверка (OpenCV)
- [ ] Валидация таймингов последовательности событий

### Этап 4 — Дуэли (реалтайм)
- [ ] WebSocket-комнаты, матчмейкинг по кубкам + режим «риск»
- [ ] Синхронный старт, трансляция статусов, результат и победитель
- [ ] Начисление кубков
- [ ] Обработка отвалов: соперник ушёл / потерял связь / DNF

### Этап 5 — Еженедельный турнир
- [ ] Скрамбл недели, одна попытка на игрока
- [ ] Общая таблица недели, автосмена по расписанию

### Этап 6 — Продакшен
- [ ] Деплой (Vercel + Railway/Render), домен, HTTPS
- [ ] Rate limiting, базовая защита API
- [ ] Онбординг: первая страница объясняет ритуал сборки
- [ ] Тест с реальными кубиками у знакомых → фикс зрения по фидбеку

## 7. Главные риски

| Риск | Митигание |
|---|---|
| Зрение нестабильно читает цвета (освещение, разные кубики, шимы/безшимные) | Этап 0 первым; калибровка цветов перед игрой; ручной фолбэк «подтвердить грань» |
| Читерство в дуэлях | Серверный скрамбл + кадры + тайминги; принять, что 100% защиты нет — цель «дорого читерить» |
| Мало игроков онлайн для дуэлей | Недельный турнир работает асинхронно и держит людей; бот-соперник как идея V2 |
| Соло-разработка, большой скоуп | Этапы независимы; после этапа 1 уже есть полезный продукт (соло-таймер со зрением) |

- Зрение корректно обслуживает полный ритуал сборки при обычных условиях
