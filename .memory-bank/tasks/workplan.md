> Разворачивает этапы из [../product-overview/vision.md](../product-overview/vision.md) в конкретные задачи.

## Этап 0 — Прототип зрения (риск-киллер) 🔴 самый важный

Цель: доказать, что зрение кубика работает. Пишем грязно, в `/prototype`, одна HTML-страница + TS. Никакого бэкенда, никакого дизайна.

### 0.1 Камера и руки
- [ ] Страница с видеопотоком (`getUserMedia`, 60 fps если доступно)
- [ ] Подключить MediaPipe Hands (JS), отрисовать landmarks поверх видео
- [ ] Зоны для рук + детект «обе руки в зонах»
- [ ] Детект неподвижности (движение landmarks < порога 500 мс)
- [ ] Конечный автомат: NO_HANDS → HANDS_IN_ZONE → READY → SOLVING → STOPPED (см. solutions П3)
- [ ] Мини-таймер на этом автомате: убрал руки — пошёл, положил — стоп

### 0.2 Чтение кубика
- [ ] Рамка-гид на экране, извлечение области кадра, сетка 3×3
- [ ] Чтение 9 наклеек: медиана центральных 50% каждой ячейки
- [ ] Калибровка по собранному кубику: показ 6 граней → 6 эталонов цвета
- [ ] Классификация: Lab + ΔE до эталонов (см. solutions П1)
- [ ] Чтение всех 6 граней перемешанного кубика с подсказками поворота
- [ ] Квоты 9×6: назначение цветов с ограничением (жадный алгоритм для начала)
- [ ] Подключить cubejs: применить скрамбл к виртуальному кубику → эталонное состояние
- [ ] Сверка считанного состояния с эталоном + отчёт какая грань не совпала
- [ ] **Профили кубиков** (утв. фича — [feature-cube-profiles](../product-overview/feature-cube-profiles.md)):
  - [ ] Исправить порядок фаз FSM: `CALIBRATE_SOLVED → SCRAMBLE_SHOWN → SCRAMBLE_VERIFY → READY → SOLVING → STOPPED → SOLVE_VERIFY` (собранный кубик ПЕРВЫМ)
  - [ ] Снятие профиля с 6 граней → localStorage (6 Lab-эталонов, без сервера)
  - [ ] Быстрая подстройка по одной грани + критерий «сошлось / не сошлось» (ΔE-порог)
  - [ ] Тест: профиль снят днём → подстройка при лампе → точность чтения не деградирует

### 0.3 Проверка на реальность
- [ ] Тест: 3 разных освещения (день, лампа тёплая, лампа холодная)
- [ ] Тест: минимум 2 разных кубика (в идеале стикерный + stickerless)
- [ ] Тест на 1–2 других людях (другие руки, другой стол)
- [ ] Замерить точность: из 20 чтений грани сколько верных

**DoD Этапа 0:** полный мини-цикл работает — калибровка → скрамбл на экране → перемешал → камера подтвердила → руки → таймер → собрал → руки → стоп → камера подтвердила сборку. Точность чтения грани ≥ 90% при нормальном свете.

**Что подучить перед этапом:** canvas API + ImageData (день), основы MediaPipe Hands JS (день, у тебя есть опыт с Pose из «Зеркала»), цветовые пространства Lab/ΔE (вечер).

⚠️ **Гейт:** если после честных попыток точность сильно ниже — стоп, возвращаемся к обсуждению (менять подход к зрению), а не идём дальше «на авось».

## Сквозные практики (весь проект)

- **Тесты** — прагматично: unit на чистую логику (цвета/квоты, подсчёт Ao5, валидация событий), ручное — на UI и зрение. Не гонись за покрытием.
- **`docs/decisions.md`** — журнал решений в одну строку («выбрала X потому что Y») — через 3 месяца скажешь себе спасибо.
- **Скриншоты/гифки прогресса** после каждого этапа — для портфолио и поста о проекте.
- **Не рефактори прототип Этапа 0 до блеска** — его судьба быть переписанным в Этапе 1, это нормально.

## Карта зависимостей этапов

```
Этап 0 (зрение) ──► Этап 1 (соло) ──► Этап 2 (аккаунты) ──► Этап 3 (честность) ──► Этап 4 (дуэли) ──► Этап 6 (прод)
                                              └────────────────────────────────────► Этап 5 (турнир) ──┘
```
Турнир недели зависит только от Этапов 2–3 — если дуэли (Этап 4) забуксуют, можно поменять их местами и запуститься с турниром раньше.
