# Почта: включить Resend

Отправка писем в коде **написана и покрыта тестами**
(`backend/app/services/email.py`: подтверждение адреса и сброс пароля, два
провайдера на выбор — Resend по умолчанию, Brevo запасной). Не хватает ключа
провайдера и трёх DNS-записей на домене.

Пока ключа нет, приложение **честно об этом кричит**: при первой же попытке
отправки в логи уходит `WARNING` с текстом «verification and password-reset mail
is SILENTLY DISCARDED». Раньше письма молча исчезали, и узнать об этом было
неоткуда.

> **Почему это надо закрыть до закрытого теста.** Сейчас `/auth/forgot-password`
> отвечает `202` и не делает ничего. Человек, забывший пароль, теряет аккаунт
> навсегда — восстановить его можно только руками в базе. Вход через Google этой
> проблемы не имеет (адрес подтверждает Google), поэтому до настройки почты
> безопаснее звать людей именно через Google.

Занимает минут двадцать плюс ожидание DNS. Бесплатного тарифа Resend (3000
писем в месяц, 100 в день) хватает с большим запасом.

---

## 1. Аккаунт и домен

1. Зарегистрируйся на [resend.com](https://resend.com) — можно через тот же
   Google-аккаунт, что владеет проектом Cubr.
2. **Domains** → **Add Domain** → `cubr-game.ru`.
3. Region оставь по умолчанию.

Resend покажет три DNS-записи. Их надо добавить там, где сейчас управляется
DNS домена (там же, где ты заводила A-запись на `135.106.181.244`).

## 2. DNS-записи

Ровно то, что показывает Resend, — не придумывай значения сама. Обычно это:

| Тип | Имя | Значение |
|---|---|---|
| `MX` | `send` | `feedback-smtp.<region>.amazonses.com` (приоритет 10) |
| `TXT` | `send` | `v=spf1 include:amazonses.com ~all` |
| `TXT` | `resend._domainkey` | длинный ключ `p=MIGfMA0…` |

Три вещи, на которых спотыкаются:

- **Имя записи.** Если провайдер DNS требует полное имя, пиши
  `send.cubr-game.ru` и `resend._domainkey.cubr-game.ru`; если он сам
  дописывает домен — оставляй как у Resend (`send`, `resend._domainkey`).
  Двойной домен в имени (`send.cubr-game.ru.cubr-game.ru`) — самая частая
  ошибка.
- **DKIM-ключ длинный** и может переноситься на несколько строк. Копируй
  целиком, без пробелов и переводов строки.
- **SPF уже есть?** Если на домене уже висит запись `v=spf1 …`, вторую
  добавлять нельзя — их должно быть ровно одна. Впиши `include:amazonses.com`
  в существующую, перед `~all`.

Дальше в Resend — **Verify DNS Records**. Проверка занимает от минуты до часа
(редко дольше). Пока статус не `Verified`, письма уходить не будут.

## 3. Ключ

**API Keys** → **Create API Key**.

- Name: `Cubr prod`
- Permission: **Sending access** (полный доступ не нужен)
- Domain: `cubr-game.ru`

Ключ (`re_…`) показывается один раз — скопируй сразу.

## 4. Положить ключ на сервер

Секрет живёт только в `/srv/cubr/.env` (права 600, владелец `deploy`), в
репозиторий не попадает.

```bash
ssh deploy@135.106.181.244
read -rs -p "Resend key: " RK; echo
sed -i "s|^RESEND_API_KEY=.*|RESEND_API_KEY=$RK|" /srv/cubr/.env
unset RK
grep -c '^RESEND_API_KEY=.\+' /srv/cubr/.env      # должно быть 1
```

Проверь заодно, что адрес отправителя на нашем домене:

```bash
grep '^EMAIL_FROM=' /srv/cubr/.env
```

Должно быть что-то вида `Cubr <noreply@cubr-game.ru>`. Если там чужой домен —
Resend откажется отправлять: разрешён только домен, который прошёл верификацию.

Перезапуск:

```bash
cd /srv/cubr && docker compose up -d api
```

## 5. Проверить живьём

1. Зарегистрируй новый аккаунт с настоящим адресом, до которого у тебя есть
   доступ.
2. Письмо «Confirm your Cubr email» должно прийти в течение минуты. Проверь и
   папку «Спам»: у свежего домена первые письма часто садятся туда, это
   нормально и проходит с репутацией.
3. Перейди по ссылке — аккаунт станет подтверждённым.
4. Отдельно проверь восстановление: `/forgot-password`, письмо «Reset your Cubr
   password», ссылка, новый пароль, вход с ним.

Если письма нет:

```bash
cd /srv/cubr && docker compose logs --tail=100 api | grep -i email
```

- `no API key` — ключ не подхватился (не тот файл, не перезапустили api);
- `Failed to send` — провайдер ответил ошибкой: чаще всего домен ещё не
  `Verified` либо `EMAIL_FROM` не на нём;
- пусто — письмо ушло, смотри в Resend → **Logs**, там видно доставку по
  каждому письму.

## 6. Что включится само собой

Как только письма поедут, заработает то, что сейчас мертво:

- подтверждение адреса при регистрации;
- восстановление пароля;
- **связывание Google-аккаунта с ранее заведённым парольным** — оно требует
  подтверждённой локальной записи (см. `UserManager.oauth_callback`), а
  подтвердить её до сих пор было нечем.

Отдельным решением остаётся, гейтить ли вход по `is_verified`. Сейчас не
гейтится нигде — то есть зарегистрироваться и играть можно, не открывая почту.
Это разумно для соло, но перед публичным запуском стоит решить осознанно.
