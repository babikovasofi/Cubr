# Отчёт — локализация RU/EN, проход 1

План: [i18n-plan.md](i18n-plan.md). Frontend-only, без зависимостей.

## Механизм

`src/i18n/t.ts` + `src/i18n/en.ts` + `src/store/langStore.ts`.

**Ключ перевода — сама русская строка** (`t("Правила")`, не `t("footer.rules")`):

- при `ru` возвращается ключ → все существовавшие тесты, ищущие русский текст,
  прошли без единой правки (592 → 607 только за счёт новых);
- при `en` непереведённое остаётся русским, а не показывает идентификатор →
  частичное покрытие деградирует мягко, и это позволило шипить проходами;
- нечего синхронизировать: забытый перевод виден глазами в диффе.

Цена зафиксирована: переформулировал русскую строку — потерял перевод.

Подстановки простые (`t("Кубки: {n}", { n })`); тест проверяет, что перевод не
теряет плейсхолдеры ключа.

## Язык

`ru` — исходный язык и дефолт. Автоподбор по `navigator.languages` срабатывает,
**только если есть рабочее хранилище**: иначе выбор некуда записать и каждый
заход угадывал бы заново. Это же решило проблему тестов — в jsdom
`navigator.language` = `en-US`, и без этого правила весь UI в тестах уехал бы на
английский. Переключатель — в футере, рядом с правилами и приватностью;
`<html lang>` меняется вместе с языком (скринридеры, автопереводчики).

## Покрытие прохода 1

Шапка/футер/меню, лендинг и дашборд, экран «открой с компьютера», все экраны
входа/регистрации/подтверждения/сброса, кнопка Google, тексты ошибок API
(переводятся в месте показа — `t(err.message)`, так как сообщения и есть ключи).

Не переведено осознанно (следующие проходы): профиль, соло-ритуал, дуэль,
турнир и скрамбл дня, длинные тексты правил и приватности. Там интерфейс
остаётся русским — видно, но не сломано.
