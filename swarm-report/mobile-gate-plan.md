# План — Этап 6: экран-заглушка для мобильных браузеров

## Зачем

R8 (`risks.md`): камера + кубик + две руки со смартфона — нерабочий UX; решение,
принятое до Этапа 1: **MVP официально поддерживает десктоп/ноутбук, на мобильных —
честный экран «играй с компьютера»**. Лендинг (Этап 6) уже публичный, значит первый
заход с телефона сейчас заканчивается сломанным ритуалом, а не объяснением.

## Скоуп

Frontend-only, без бэкенда/миграций/зависимостей.

**Гейтим только ритуальные роуты** (там, где нужна камера + обе руки):
`/solo`, `/tournament`, `/daily`, `/duel/join/:token`, `/duel/:roomId`.

**НЕ гейтим:** `/` (лендинг — маркетинг, его читают с телефона), `/rules`, `/privacy`,
логин/регистрацию/сброс пароля, `/onboarding` (в нём есть «пропустить» и настройки
профиля — заблокировать значит запереть свежезарегистрированного мобильного юзера),
`/profile`.

## Детекция

`(hover: none) and (pointer: coarse)` — «основной ввод = палец». Осознанно **без
ширины экрана**: узкое окно на десктопе — не телефон, а resize/ротация не должны
выбивать человека из активной сборки. Ноут с тачскрином даёт `hover: hover` → не гейтится.
Планшет (iPad, включая iPadOS с «десктопным» UA) даёт `hover: none` → гейтится,
и это правильно: ритуал одинаково неудобен.

Фолбэк, если `matchMedia` недоступен: `maxTouchPoints > 0` И мобильный UA.
Чистая функция `isHandheldDevice(probe)` — вся матрица покрыта юнит-тестами.

## Escape hatch

Кнопка «Всё равно открыть здесь» → `sessionStorage: cubr_handheld_override`
(zustand `deviceStore`, чтобы гейт и подсказка на лендинге видели одно состояние).
Причина: ложные срабатывания (планшет с клавиатурой, экзотический браузер) не должны
делать продукт недоступным; ограничение — сессия, не навсегда.

## Экран-заглушка

Карточка в языке §5.5/§1: заголовок «Сборку судит камера компьютера», честное
объяснение почему (руки заняты кубиком, камера телефона смотрит не туда), адрес сайта
+ «Скопировать ссылку» (`navigator.clipboard`, guarded), ссылки «Правила» / «На главную»,
мелкой строкой — escape hatch.

Плюс на лендинге с телефона — строка вместо «Нужен компьютер с камерой…»: честно
предупредить ДО клика по CTA.

## Test plan

- `tests/lib/device.test.ts` — матрица: coarse+no-hover → true; fine pointer → false;
  hover+coarse (тачскрин-ноут) → false; нет matchMedia + мобильный UA + touch → true;
  нет matchMedia + десктопный UA → false; matchMedia кидает → false (не гейтим по ошибке).
- `tests/components/DesktopOnlyGate.test.tsx` (jsdom) — телефон: дети НЕ отрендерены,
  видна заглушка; десктоп: дети отрендерены, заглушки нет; клик по escape hatch →
  дети появляются; смена media (`change`) переоценивает; копирование ссылки.
- `tests/pages/HomePage.test.tsx` — с телефона лендинг показывает мобильное
  предупреждение вместо десктопной строки требований.
- Регресс: весь `npm run test` + `typecheck` + `lint` + `build`.
