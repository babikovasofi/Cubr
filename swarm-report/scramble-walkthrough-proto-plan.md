# Plan: Прототип визуального walkthrough скрамбла   (slug: scramble-walkthrough-proto)

> planner + skeptic (оркестратор вручную). Skeptic verdict = **revise**; его HIGH/MED
> вложены — главное переформулирование цели ниже.

## TL;DR
Отдельный dirty vanilla-TS прототип (`prototype2/`, Этап-0-стиль) визуального пошагового
walkthrough скрамбла на **cubing.js / `<twisty-player>`**: анимирует ходы по одному,
фикс. ориентация, назад/дальше + клавиатура, прогресс, мини-карта, тумблер картинки/
нотация. Цель — **де-риск библиотеки `cubing` (заменит cubejs) под Vite + проверка
понятности анимации не-кубером**, перед портом в Этап 1.

## Что этот прототип ДОКАЗЫВАЕТ и что НЕТ (skeptic HIGH#1/#2/MED#5)
- ✅ **Техника:** `cubing/scramble` (`randomScrambleForEvent('333')`, async) + `cubing/twisty`
  (`<twisty-player>`, web-component) реально работают под Vite **в dev И в прод-build**
  (тот же класс риска, что cubejs-gotcha — worker/WASM/asset-загрузка).
- ✅ **Понятность:** не-кубер понимает «какой слой и куда» из анимации + токена + короткой
  подписи направления по-русски.
- ❌ **НЕ доказывает §4.3.1** (новичок собирает физически ВЕРНЫЙ скрамбл). Без камеры
  ориентация кубика — «на честном слове»: ошибка на шаге 1 (кубик повёрнут не так) тихо
  ломает все ходы, приложение об этом не знает. Физкорректность **отложена в Этап 1**, где
  есть камера (можно подтвердить «белый верх/зелёный фронт» существующей vision-логикой).
- Честный UX: приложение показывает **задуманное** состояние, НЕ твой реальный кубик; не
  обещаем «поймай свою ошибку на лету». Отдельный vanilla-прототип оправдан ТОЛЬКО как
  throwaway-спайк; сама shippable-фича собирается в React-приложении Этапа 1.

## Acceptance criteria (наблюдаемо в браузере prototype2)
1. **Build-де-риск (главное):** `npm run dev` (127.0.0.1) И `npm run build` + `vite preview`
   — оба показывают рабочий `<twisty-player>` с анимацией. Прод-бандл не падает (проверить,
   как cubejs падал только в рантайме). Замерить размер бандла.
2. Генерится случайный 3x3 скрамбл через `randomScrambleForEvent('333')` (async, awaited,
   НЕ на module-scope); walkthrough = M шагов (M = число токенов, ~18–22), только повороты
   слоёв (U/D/R/L/F/B), без x/y/z.
3. На каждом шаге `<twisty-player>` проигрывает ровно ОДИН ход как анимацию; **направление
   хода однозначно** дано не только анимацией: показываем токен (`R'`, `F2`) + короткую
   русскую подпись («правый слой — вниз к себе», «×2 — пол-оборота») — **токен/подпись =
   источник истины** (анимация направления неоднозначна для новичка, skeptic HIGH#3).
4. «дальше →» проигрывает следующий ход; «← назад» анимирует ОБРАТНЫЙ ход (инверсия), не
   рескрамбл. Клампинг [0..M]; на последнем «дальше» — «Готово (проверка камерой — Этап 1)».
5. Первый экран — русская инструкция ориентации + **постоянный баннер** «Держи кубик белой
   гранью вверх, зелёной к себе. НЕ поворачивай кубик целиком» (skeptic HIGH#3). twisty
   зафиксирован white-top/green-front, не вращается целиком между шагами.
6. На шаге N кубик отражает реальное состояние после первых N ходов (перемотка туда-обратно
   консистентна). Ground truth из ТОЙ ЖЕ cubing-alg (не смешивать с cubejs, skeptic MED#6).
7. Прогресс «шаг N из M» (рус.) + бар. Мини-карта: миниатюры всех ходов, текущий подсвечен,
   клик = прыжок; **миниатюры — лёгкий 2D SVG-рендер cubing, НЕ 20 WebGL-твисти** (skeptic LOW).
8. Тумблер «картинки / нотация»: нотация показывает всю строку одним блоком; выбор в
   localStorage, восстанавливается.
9. Клавиатура: ←/→ листают, Пробел = дальше; `preventDefault` (не скроллить страницу);
   не конфликтует с фокусом twisty-player (skeptic LOW).
10. Все подписи/кнопки на русском. Существующий `prototype/` НЕ тронут.

## Plan (файлы под prototype2/)
**Шаг 1 — ГЕЙТ-СПАЙК (сначала, skeptic MED#4):** минимальная страница — `await
randomScrambleForEvent('333')` → смонтировать `<twisty-player alg=…>` → проверить `npm run
dev` И `npm run build`+`preview`. Если прод/воркеры/wasm не резолвятся под Vite — заложить
конфиг (`optimizeDeps` / asset-хендлинг) или patch-подобный обход, как с cubejs. Не идти
дальше, пока и dev, и build не зелёные.

- `prototype2/{package.json, tsconfig.json, .gitignore}` — новый Vite+TS+Vitest корень; dep
  `cubing`; БЕЗ cubejs/mediapipe/patch-package. (Обоснование отдельного каталога: cubing
  заменяет cubejs — не держать обе либы в одном package.json; чистый Vite root; ноль риска
  задеть vision-риг.)
- `prototype2/scramble.ts` — async обёртка `randomScrambleForEvent('333')` + парс строки →
  `moves[]`. Изолирует импорт либы и async.
- `prototype2/walkthrough.ts` — **ЧИСТАЯ** шаг-машина (без DOM/cubing): `{moves,index}`,
  `next/prev/goto` с клампингом, `algUpTo(n)`, `moveAt(n)`, `progressFraction`, `isFirst/isLast`.
  Ядро под Vitest.
- `prototype2/twisty.ts` — обёртка `<twisty-player>`: динамический импорт `cubing/twisty`
  (регистрация web-component ПОСЛЕ DOMContentLoaded), фикс ориентация white-top/green-front,
  `setAlg/jumpTo(index)/playStep(from,to)` (назад = анимированная инверсия), лёгкий 2D-рендер
  для миниатюр. Весь риск загрузки — тут.
- `prototype2/moveCopy.ts` (нов, из skeptic HIGH#3) — маппинг токен→русская подпись направления
  (`R`→«правый слой вниз к себе», `R'`→«правый слой вверх», `U2`→«верх ×2 (пол-оборота)» …).
  Чистая функция, под Vitest.
- `prototype2/main.ts` — склейка: await скрамбл → walkthrough → бинд кнопок/клавиатуры →
  прогресс/бар/мини-карта → twisty.playStep → баннер ориентации → тумблер+localStorage. Рус.
- `prototype2/index.html`, `style.css` — крупный twisty, баннер ориентации, прогресс+бар,
  кнопки, мини-карта, тумблер/блок нотации, подпись направления шага.
- `prototype2/tests/{walkthrough,moveCopy}.test.ts` — Vitest на чистую логику (клампинг,
  next/prev, goto, algUpTo, progress, first/last; токен→русская подпись).
- `prototype2/README.md` — рус.: что это (throwaway-спайк cubing, заменит cubejs, не связан с
  prototype/), запуск (`npm i`, `npm run dev -- --host 127.0.0.1`), статус.

**Тесты:** Vitest на `walkthrough.ts` + `moveCopy.ts` (чистая логика). `<twisty-player>`
рендер/анимация + build-де-риск — ручная браузерная QA (web-component headless не гоняется).
Опц. Node-smoke `scramble.ts` (если либа работает в node Vitest; если тянет worker/WASM —
только браузер).

## Assumptions
- `prototype2/` отдельно (обосновано). Пакет `cubing` экспортирует `cubing/scramble` +
  `cubing/twisty`; точные подпути/параметр ориентации уточнить по README пакета на Шаге 1
  (версия latest).
- «Один ход за шаг» = каждый токен; F2 анимируется как один двойной поворот.
- Стрелка-оверлей поверх картинки — опционально; направление несёт токен+русская подпись (обяз.)
  + анимация. Отдельный SVG-слой стрелки не блокирует приёмку.
- Vite биндит IPv6 → dev с `--host 127.0.0.1` (прошлый гоча).
- Чистый `walkthrough.ts`/`moveCopy.ts` переживут порт в React как есть; twisty/main
  переписываются под React-обёртку.
