# План — Этап 6: фильтр слов для ников

## Зачем

Чеклист Этапа 6 (`workplan.md`). Публичная поверхность одна — `public_handle` на
бордах турнира/скрамбла дня (П10: борды показывают ТОЛЬКО его или «Аноним»).
`nickname` сейчас виден лишь самому владельцу, но фильтруем и его: (а) он может
всплыть в UI позже, (б) один валидатор на оба поля дешевле двух политик.

## Где врезка

Не в pydantic-схеме: pydantic отдаёт 422 со списком `detail[]`, а фронтовый
`parseErrorBody` понимает `detail: {code, reason}` — 422-массив у него схлопнется
в «Что-то пошло не так». Значит валидация в `UserManager.create/update`
(`services/auth.py`), ошибка — `HTTPException(400, detail={"code", "reason"})`,
как уже сделано для лимита кубиков (`CUBE_LIMIT`).

Покрываемые точки: регистрация (`POST /auth/register` c `nickname`),
`PATCH /users/me` (`nickname`, `public_handle`), OAuth-деривация ника из
email-локалпарта (санитайз, не 400 — падать посреди OAuth-редиректа нельзя).

## Как фильтруем — `services/moderation.py`

Правила по порядку (первая сработавшая — ответ):

1. `NAME_TOO_SHORT` — < 2 значащих символов.
2. `NAME_INVALID_CHARS` — вне алфавита `[A-Za-zА-Яа-яЁё0-9 _.-]` (эмодзи,
   zero-width, RTL-override — типовой инструмент impersonation) или нет ни одной буквы.
3. `NAME_RESERVED` — служебные имена (admin/админ/support/cubr/модератор/судья…):
   выдача себя за администрацию.
4. `NAME_NOT_ALLOWED` — мат/оскорбления.

**Обход через похожие символы.** Скелет строится дважды: латиница→кириллица (для
русских корней) и кириллица→латиница (для английских), плюс leet-цифры (`0→о`,
`3→е`, `4→ч/a`, `1→i`, `@→a`, `$→s`), выброс всего, что не буква, и схлопывание
повторов (`пииидор` → `пидор`). Иначе `xyu` / `п1здец` / `f_u_c_k` проходят насквозь.

**Ложные срабатывания.** Корни разделены на два списка:
- подстрочные (`пизд`, `бляд`, `хуй`, `fuck`, `nigg`…) — однозначны внутри слова;
- пословные (`жид`, `хач`, `rape`, `dick`) — только целым токеном, иначе
  «жидкость», «хачапури», «grape», «Dickens» уедут в бан.
Схлопывание повторов делает `суккуб` → `сукуб`, поэтому корень — `сука`/`суки`, не `суку`.

## Test plan (backend, pytest)

- `tests/test_moderation.py` — чистая функция: чистые ники проходят (вкл. русские,
  дефисы, цифры); мат ловится; обходы ловятся (латиница-омоглифы, leet, разделители,
  повторы); **ложные срабатывания НЕ ловятся** (Александр, ребята, скипидар,
  мандарин, суккуб, Херсон, grape, Dickens, жидкость, хачапури); зарезервированные;
  эмодзи/zero-width/RTL; пусто/None (ник необязателен).
- `tests/test_auth.py` (или новый `test_profile_names.py`) — регистрация с матерным
  ником → 400 `{code: NAME_NOT_ALLOWED}`; `PATCH /users/me` с матерным `public_handle`
  → 400; чистое имя → 200 и сохранилось; OAuth-деривация из грязного email-локалпарта
  → безопасный fallback, регистрация не падает.
- Регресс: весь backend pytest, ruff/mypy.
