# План — локализация RU/EN

Роадмап, «Технологическое»: `Локализация RU/EN 🟢 ⭐⭐`. В `src` ~1064 русских
строки в 83 файлах — за один проход это не переводится, поэтому механизм должен
переживать **частичное** покрытие без уродства.

## Механизм: русская строка = ключ

`t("Правила")`, а не `t("footer.rules")`.

- При `lang === "ru"` `t()` возвращает сам ключ → все 592 существующих теста,
  которые ищут русский текст, продолжают проходить без правок.
- При `lang === "en"` возвращается `EN[ключ] ?? ключ` → непереведённое место
  остаётся русским, а не превращается в `footer.rules` на экране.
- Ключи не надо выдумывать и синхронизировать: диффы читаемы, забытый перевод
  виден глазами, а не через отчёт покрытия.

Цена: переформулировал русскую строку — потерял перевод. Для двух языков и
одного разработчика это дешевле, чем реестр ключей.

Подстановки — простые: `t("Осталось {n}", { n: 5 })`, замена по `{name}`.

Никаких зависимостей (i18next и подобное — лишние килобайты ради `Map`).

## Язык

`store/langStore.ts`: `ru` по умолчанию, `localStorage: cubr_lang`, при первом
заходе — `navigator.language.startsWith("en") ? "en" : "ru"`. Переключатель в
футере (единственная сквозная точка, как ссылки на правила).
`<html lang>` обновляется вместе с языком — это читают скринридеры и переводчики.

## Порядок проходов

1. **Этот проход:** механизм + переключатель + публичная поверхность целиком —
   лендинг, правила, приватность, шапка/футер, экраны входа/регистрации/
   восстановления, тексты ошибок API. Человек с улицы на английском понимает,
   что это, и заводит аккаунт.
2. Следующие проходы: профиль, соло-ритуал, дуэль, турнир/скрамбл дня.
   До перевода эти экраны остаются русскими — это видно, но не сломано.
